# Database Set-up

<Badge color="gray">SOP-CR-104_04</Badge> <Badge color="gray">Version 04</Badge> <Badge color="green">Effective 01 Sep 2018</Badge> <Badge color="blue">Sponsor-Investigator</Badge>

<Note>
This SOP describes the tasks necessary to generate, test, implement, and approve a database set-up for a study to ensure accurate, reliable, complete, and secure electronic data. It applies to all study databases requiring set-up at the RI-MUHC and to all Data Management and IT personnel responsible for database set-up.

## Key points

- The study database must be built according to the **<Tooltip tip="Document designed to record all protocol-required information to be reported to the sponsor for each participant." headline="Case Report Form (CRF)" cta="Full definition" href="/kb/glossary#crf">CRF</Tooltip> designs** ([SOP-CR-100](/sops/cr-100)) and the **Data Management Plan** ([SOP-CR-103](/sops/cr-103)). Do not begin database build until both documents are finalized and approved.
- **User access must be role-based**: data entry users, data managers, statisticians, and auditors must each have access only to the functions they need. Access levels must be documented.
- The database must have a **complete audit trail** that captures all entries, edits, and deletions with user identifier, date, and time — this is a regulatory requirement and cannot be disabled.
- **User Acceptance Testing (UAT)** must be completed and documented before the database is opened for participant data entry. UAT documentation must be retained in the <Tooltip tip="The sponsor's collection of documentation demonstrating compliance across all study sites." headline="Trial Master File (TMF)" cta="Full definition" href="/kb/glossary#tmf">TMF</Tooltip>.
- At the RI-MUHC, **REDCap** is the supported eCRF platform for studies with ≤1,000 variables → [SOP-CR-014](/sops/cr-014). For larger or more complex databases, consult the Clinical Research Hub.
- The database must be configured in a **test environment** first; only after successful testing and sign-off should the production database be opened for data entry.
