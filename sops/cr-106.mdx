<a id="purpose"></a>

### 1.0 Purpose

This Standard Operating Procedure (SOP) describes the steps required during the transfer of external files to and from the study database to preserve the integrity of transmitted data and the study database.

<a id="scope"></a>

### 2.0 Scope

This SOP is applicable to all data files that are part of the study data set and which are transmitted from another site to be included in the study database. This SOP is also applicable to those personnel responsible for the transmission, such as all the Data Management and Information Technology (IT) personnel, unless otherwise stated in the study contract or data management plan.

<a id="responsibilities"></a>

### 3.0 Responsibilities

The Sponsor-Investigator or Qualified Investigator (<Tooltip tip="The physician responsible to the sponsor for the conduct of a clinical trial at the site. One QI per study per Canadian site." headline="Qualified Investigator (QI)" cta="Full definition" href="/kb/foundations/glossary#qi">QI</Tooltip>)/Investigator, Data Management and IT personnel (if applicable) are responsible for ensuring that the processes involved in all database file transfers, from or to the study database, meet all of the applicable regulatory, International Conference on Harmonisation (ICH), Good Clinical Practice (GCP), Sponsor, and local requirements.

Any or all parts of this procedure may be delegated to appropriately trained study team members, but remain the ultimate responsibility of the Sponsor, Sponsor-Investigator and/or Qualified Investigator (QI)/Investigator.

<a id="definitions"></a>

### 4.0 Definitions

Database: The term database applies to all computer software which is used to format, manipulate or control storage of the electronic data for the study. This may be one computer file or a system of files which are maintained as the study database.

See also, “CDISC Clinical Research Glossary, Version 9.0” and “N2 Glossary of Terms”.

<a id="procedure"></a>

### 5.0 Procedure

<a id="5-1"></a>

#### 5.1 Treatment coding and blinding

<a id="5-1-1"></a>**5.1.1** Where necessary, maintain the blinding of the treatment coding in released datasets. This may mean removing the treatment codes or replacing the treatment codes with mock codes. Document the recoding and include notification of the re-coding/blinding with the transmitted file.

<a id="5-2"></a>

#### 5.2 Data security

<a id="5-2-1"></a>**5.2.1** Maintain appropriate authorizations for access to data to be transferred/ received.

<a id="5-2-2"></a>**5.2.2** Ensure that the receiving site is aware of privacy legislation regarding the use of linked data.

<a id="5-2-3"></a>**5.2.3** Encrypt files for transfer using local encryption methods and software. Files may also be transferred as password protected compressed archives or transferred directly using encrypted file transfer.

<a id="5-2-4"></a>**5.2.4** Ensure that the original data files that are to be received by the data centre and that are to be transferred into the study data base are write protected and are included in the data archiving process.

<a id="5-2-5"></a>**5.2.5** Maintain a copy of all files of the originating study database before they are transmitted externally. Ensure the copy is write protected and is included in the data archiving process.

<a id="5-2-6"></a>**5.2.6** Point-to-point file transfers or utilization of authorized “drop file” facilities are used when available. File drop/exchange services, provided by many institutions, utilize file encryption and secure transmission. File transfer via an email message is a secondary option.

<a id="5-2-7"></a>**5.2.7** Passwords are always sent to the recipient of the data files in a separate transmission

<a id="5-3"></a>

#### 5.3 Documentation and verification

<a id="5-3-1"></a>**5.3.1** Ensure that the data file is accompanied by documentation of the content and format.

- If applicable use export/import functions for creating/reading transport files and ensure that the appropriate documentation is associated to the transport.
- The minimum information should include:
  - The column positions or delimiter
  - The column headings
  - The field formats for all columns
  - The field lengths for all columns

<a id="5-3-2"></a>**5.3.2** In cases where transferred data are converted to a different format, verify the data conversion by comparing the transferred fields to original field specifications.

<a id="5-3-3"></a>**5.3.3** When feasible, provide/verify the number of observations (rows) and number of variables (columns) in the transferred file.

<a id="5-3-4"></a>**5.3.4** Request documentation from the receiving site or provide documentation to the transmitting site to ensure that the file was received and verified.

### 1.0 Specific RI-MUHC policies and procedures

<a id="1-1"></a>

#### 1.1 Data sharing/transfer agreement

Prior to transfer or sharing of information (partial or entire data) to a non-MUHC site or prior to receiving information (partial or entire data) from a non-MUHC site, a Data Sharing/Transfer Agreement must be in place by all parties (Disclosing Party and Receiving Party).

A template Agreement must be obtained from the RI-MUHC Contracts Office via contracts@muhc.mcgill.ca.
