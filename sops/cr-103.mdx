## Purpose and scope

This SOP identifies the need for a Data Management Plan (DMP) and describes which parties are applicable, the purpose, the process for creating a DMP, and the essential components.

This SOP is applicable to all Data Management personnel, or other research team members, who are responsible for authoring or versioning a Data Management Plan for Sponsor-Investigator studies.

---

## Responsibilities

The **Sponsor-Investigator, QI/Investigator, and applicable Data Management personnel** are responsible for ensuring that all study data management activities meet all applicable regulatory, ICH-GCP, Sponsor, and local requirements.

---

## Procedure

### 5.1 Purpose of the DMP

**5.1.1** The Data Management Plan (DMP) is a formal document that describes how data will be collected, entered, verified, validated, queried, corrected, transferred, and stored throughout the study. The DMP must be in place and approved before the database is built → [SOP-CR-104](/sops/cr-104).

**5.1.2** The DMP must align with:
- The study protocol → [SOP-CR-102](/sops/cr-102)
- The CRF designs → [SOP-CR-100](/sops/cr-100)
- The database setup plan → [SOP-CR-104](/sops/cr-104)

Changes to one document typically require updates to the others.

### 5.2 Essential DMP components

The DMP must address the following at a minimum:

| Component | Description |
|---|---|
| Data collection method | Paper CRF, electronic CRF (eCRF/EDC), or both; applicable platforms (e.g., REDCap) |
| Source data identification | Definition of source data, source documents, and source data verification approach |
| Data entry | Who may enter data, data entry timelines, double data entry requirements if applicable |
| Data validation rules | Range checks, consistency checks, required fields, cross-field logic rules |
| Query management | Process for raising, resolving, and closing data queries; roles and timelines |
| Protocol deviations tracking | How deviations are flagged, documented, and resolved in the database |
| Data transfer | Method, format, encryption, documentation, and recipient confirmation for any data transfers |
| Database security | User access controls, password policy, audit trail requirements |
| Backup and disaster recovery | Backup frequency, method, storage location, and recovery testing |
| Database lock procedure | Criteria for lock, roles, timeline → [SOP-CR-107](/sops/cr-107) |
| Data archiving | Location, format, and retention period for archived data → [SOP-CR-015](/sops/cr-015) |

### 5.3 Roles and responsibilities in the DMP

**5.3.1** The DMP must define roles and responsibilities for data management activities, including:
- Who may enter, edit, and query data
- Who approves data queries
- Who performs data validation checks
- Who manages database access
- Who is responsible for backups
- Who authorizes and performs database lock → [SOP-CR-107](/sops/cr-107)

### 5.4 Version control and filing

**5.4.1** The DMP must be version-controlled. Each version must have a version number and date clearly indicated.

**5.4.2** All revisions to the DMP must be documented with a new version number, date, and summary of changes.

**5.4.3** The completed and approved DMP must be filed in the Trial Master File (TMF). Superseded versions must be retained.
